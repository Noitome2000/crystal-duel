# 晶界 · 双人战棋

在线游玩：**https://Noitome2000.github.io/crystal-duel/**

无需安装，手机和电脑浏览器均可打开。支持电脑对战和同屏双人；当前没有异地联网对战。

## 手机操作

- 点选英雄先查看放大的技能说明，再点同一个英雄确认；也可以点“选择…入阵”按钮。游戏文字已禁用长按选取。
- 点击棋子或下方阵容选择单位，直接点绿格移动或点红色目标攻击；主动技能使用棋盘下方的大按钮。
- 点击亮起的落点执行；单指拖动旋转棋盘，双指张合缩放，“复位视角”恢复默认视角。
- 竖屏和横屏均可使用，较小屏幕可以上下滚动查看阵容、技能和记录。

## GitHub Pages 部署

推送到 `main` 后，GitHub Actions 自动执行规则测试、打包并发布至 Pages。仓库 Settings → Pages 的发布源设为 **GitHub Actions**。

无需安装 npm 依赖。需要 Node.js 20 或更新版本：

```sh
npm test
npm run build
npm run preview
```

本地预览地址为 `http://127.0.0.1:4173/crystal-duel/`，与 Pages 子目录部署方式一致。`dist/` 只包含白名单内的网页和素材，不包括本地文档、工具或凭证。

## 离线启动


双击 **晶界 · 开始游戏.lnk**，在独立的 Edge 窗口中开始游戏。没有终端、端口、Python 或在线依赖；关闭游戏窗口即可。

也可以直接双击 **index.html**，用 Edge / Chrome 离线游玩。若系统禁用 VBScript，请使用这个入口。移动整个文件夹后，若快捷方式失效，可双击 **launch.vbs** 或 **index.html**。旧的 `启动游戏.bat` 已改为直接打开页面，不再启动服务。

## 操作

- 先投掷硬币决定先手，再按“先手 1 号位 → 后手 1 号位 → 先手 2 号位 → 后手 2 号位”选将，完成后自动由先手行动。
- 工具栏的“AI 自我对抗”打开独立训练面板，可设置模拟局数、先手安排、搜索强度，并为赤方和靛方四个席位分别指定英雄或随机选将。结束后显示先后手和每个英雄的表现分。
- “英雄表现”可独立切换历史累计 / 本轮模拟，并导出当前范围的英雄统计。历史累计自动读取已保存的当前规则自我对抗，排除模型验证和不兼容记录；本轮为本页面最近一轮，新一轮开始时重置，刷新后已保存记录仍可在历史累计中查看。
- “英雄组合”显示全部 45 种双英雄组合的出场、胜负、平局、未完成、表现分和先后手胜率及样本数，支持历史累计 / 本轮切换、排序、英雄筛选及组合对阵明细。组合合并上下位置，逐局记录保留位置；双方同组合各算一次出场，对阵按赤方 × 靛方区分颜色。未出场显示“—”，平局与未完成不进入胜率分母，少于 20 局胜负样本标为样本偏少。
- 历史组合统计从已保存的当前规则自我对抗记录重新汇总，自动兼容旧记录，排除新旧模型验证局和不兼容记录。不同搜索强度及模型会合并，统计是实测表现，不是固定英雄强度。“导出组合统计”导出所选范围全部组合；本轮报告、完整训练数据、本地文件夹快照和 GitHub 同步也包含组合数据。
- “选择本地训练文件夹”可把对局、模型和统计保存到 `crystal-duel-training.json`，下次恢复或导入后重新汇总。浏览器目录授权只保存在当前浏览器中，不导出到 JSON；跨浏览器使用同一文件需分别授权目录。
- 每局自我对抗会保存可回放的行动轨迹和局面特征到浏览器本地训练库。累计记录达到门槛后会生成候选模型，经过独立对局验证才会启用；训练数据和模型可导出。
- 训练页也提供可选的 GitHub 同步：填写对目标仓库有 `Contents: write` 权限的 fine-grained token 后，数据会通过 GitHub Contents API 提交为 `training-data/training-dataset.json`。token 只保存在当前页面内存，不会写入仓库。
- 默认电脑执靛方，你执赤方；也可在投币前选择本地双人。电脑轮到自己的席位时自动选将。
- 点击棋子或侧栏单位，默认同时显示移动和攻击落点，点绿格移动、点红色目标攻击；技能在围绕底座的分离圆环中选择。选定后轮盘收起；再次点击棋子可展开，快捷键 1 / 2 返回移动与攻击一体的默认行动，3 起依次选择技能；无可用主动技能时不显示技能扇区，多种共享技能分别显示。
- 点击棋盘或页面空白处关闭轮盘，再点击己方单位可重新打开；旋转与缩放时轮盘和棋盘使用同一帧的相机投影。
- 选将界面始终显示双方的两个席位，已选英雄用完整名称和图形徽记展示；悬停或键盘聚焦英雄卡片可查看技能详情。
- 攻击落点预先高亮，悬停可预览逐格路径；攻击沿路径移动并保留残影。游侠防守时标出攻击者，选定闪避方向后播放逼近、慢动作和瞬闪，再由原攻击棋子从攻击落点重新行动。技能发动前显示名称与爆发残影。拖动旋转、滚轮缩放、复位按钮恢复视角。
- 连击、游侠瞬闪与游击都有明确的继续 / 结束选择。魔术师在技能按钮下选择要交换的一对单位。巨龙蓄力后在下个己方回合选择落点。
- 页面中的规则手册列出十种英雄与具体约定。

## 规则依据与约定

以《规则.docx》和关联任务最后的用户修正为准：中央 4×4、左右各两格凸起；蓝格英雄，内侧绿色纵列为士兵。普通移动一格；士兵攻击走满三格、英雄走满两格；可沿四方向转弯，不穿人、不重复经过单次路径中的格子。相邻的目标也可能通过合法的三格绕行被攻击，距离按实际路径计算。

文档未完全定义的细节采用以下约定，并在规则手册中明示：

- 一回合冷却指跳过下一次己方行动，再下一次恢复；共享冷却记在提供能力的英雄上。
- “相邻”及周围八格包含斜向；普通走路仅横纵四方向。
- 反推保护覆盖被推者下个回合；换位保护到受影响单位下个回合结束。
- 开局六次行动内禁用攻击与大部分技能，先锋陷阵、骑士神速（含共享）例外。
- 可主动结束连击；普通连击只攻击士兵；先锋和狼灭能在连击中攻击英雄。
- 没有合法行动时可交接回合；未擅自增加未定义的平局或回合上限规则。
- 场上棋子不大于 3 个后开始残局计数；双方再完成 20 步仍未决出胜负时，按棋子数量、单子英雄优先、同种类后手优先依次检定。连击、闪避和游击不额外计步，吃子不重置计数。

## 验证

`node tests/statistics-browser.cjs`：组合统计、历史导入去重、镜像阵容、先后手拆分、筛选排序、导出、本地目录恢复和手机布局回归。`node tests/training-browser.cjs` 另验证真实对弈、训练、模型验证与组合统计贯通。

`node tests/skills-browser.cjs`：技能施放、命中表现、被动触发、设陷束缚、共享能力、蓄力与移形保护的浏览器回归。

`node tests/mobile-pages.cjs`：先启动本地预览，验证 320/390/430 像素竖屏和手机横屏的触屏选将、移动、双指缩放、规则弹窗及素材加载。可设置 `GAME_URL` 改测线上地址。

`node tests/combo-browser.cjs`：连续三次吃子、已退场棋子与攻击者坐标重合、动画异常恢复与终局回归。

`node tests/combat-browser.cjs`：动态多技能轮盘、共享冷却、技能爆发、逐格攻击轨迹、游侠攻击来源提示与慢动作瞬闪、原攻击者额外行动。

`node --test tests/rules.test.cjs`：纯规则回归测试，包含随机对局不重叠、不出界检查。

`node --test tests/ai.test.cjs tests/draft.test.cjs`：电脑战术、特殊阶段与投币选将顺序测试。电脑采用有预算限制的 Minimax 搜索，具体评分、搜索步骤与局限见 [AI说明.md](AI说明.md)。

`node tests/ui-ai.cjs`：轮盘跟随与收起、电脑自动行动、重开取消旧决策、双方游侠反应、巨龙终局及手机边界验证。

`node tests/draft-browser.cjs`：两种投币结果、逐席选将、自动开局、英雄编号部署和选将页面布局验证。

`node tests/ui-polish.cjs`：快速旋转时的逐帧轮盘对齐、空白处关闭、合法移动、完整英雄名称、已选阵容和四种窗口尺寸无溢出验证。

`node tests/browser.cjs`：Playwright / Edge 浏览器验证，涵盖 file:// 离线启动、选将、移动点击、开局保护、拖动不误操作、实际对局、重开和窄屏；需要安装 Playwright 或设置 `PLAYWRIGHT_MODULE` 为其路径。本机测试也可使用 Codex 提供的依赖。

`artifacts/` 保存改动前的三个前端文件、规则原图及浏览器实测截图。第三方 Three.js 0.160.0 已保存在 `vendor/`，许可见 `vendor/THREE-LICENSE.txt`。
